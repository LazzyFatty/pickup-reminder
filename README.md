# 取件提醒

离线整理安卓短信里的快递取件码。包名 **`ren.haom.pikeupcode`**，当前版本 **1.1.1**，Android 8.0 及以上。

## 功能

- 收到普通短信时，在本机识别取件语义与取件码，长短信合并后再解析。
- 首页为待取列表；点击「标记已取」移入历史，支持撤销和恢复待取。
- 新短信识别出新包裹后，通知栏突出显示取件码和驿站位置；点击进入对应包裹。重复短信、手动粘贴和历史导入不会反复通知。
- 待取和已取列表都可长按单条卡片删除，二次确认后删除，底部提供约 5 秒的「恢复」。删除只影响应用内记录；去重摘要保留，避免再次导入时复活。
- 卡片副标题显示物流单号或尾号和时间，没有单号时只显示时间。
- 提取取件码，以及短信中可确认的快递公司、驿站名称、地址、物流单号或尾号、联系电话和网址。缺失字段留空。
- 设置已取记录保存天数，默认 30 天，可输入非负整数，**0 为永不删除**。从标记已取时起算，只清理已取记录。
- 桌面小组件显示待取包裹总数和全部取件码，窄时单列、宽度足够时每行两条；调整大小后自动更新，取件码自动缩放，列表可滚动，点击进入详情。
- 可粘贴短信识别，也可在设置中导入近 7 天短信；导入会去重。
- 官方 Material Design 3 组件、底部导航、卡片、对话框与输入框，适配系统深浅色。

## 安装和使用

1. 正式版从仓库的 [Releases](https://github.com/LazzyFatty/pickup-reminder/releases) 下载。要测试最新提交，可在 [Actions](https://github.com/LazzyFatty/pickup-reminder/actions) 的成功运行中下载 Artifacts。也可以按 [打包与签名指南](docs/signing.md) 自行构建。
2. 在首页或设置里开启短信识别，授予「接收短信」权限。Android 13 及以上另需允许通知；设置里可开启或管理取件通知。拒绝通知权限不影响包裹入库。
3. 需要已有短信时，在设置里选择「导入近 7 天短信」，另行授予「读取短信」权限。导入的已取包裹请核对后手动标记。
4. 设置里点击「添加到桌面」，或长按桌面空白处 → 小组件 → 取件提醒。

部分厂商系统需要额外开启自启动、后台运行和通知类短信权限。系统强行停止应用后，不会继续分发短信广播，需重新打开。短信权限属于 Android 受限权限；若安装器不允许授权，可使用支持受限权限白名单的安装器或 `adb install -r APK路径` 后到应用内授权，无需设为默认短信应用。

## 离线与数据

应用不声明 `INTERNET` 权限，无账号、广告、统计或云端识别。短信与包裹记录保存在应用私有 SQLite 数据库中，关闭 Android 云备份和设备迁移备份。只有明确含取件码的短信会入库；其他短信仅在处理期间读取。

复制取件码会写入系统剪贴板。拨号交给系统拨号界面，不会直接拨出。点击网址会先确认，再交给外部浏览器；浏览器可能联网。

清理已取记录会删除其短信原文和字段；保留不可逆的 SHA-256 去重摘要，以免重新导入收件箱时恢复已清理记录。卸载应用会删除本地记录，**当前未提供导出或备份功能**。

定期清理由系统 JobScheduler 安排，后台调度可能推迟；打开应用、查看列表或收到短信时也会清理。

## 识别边界

优先识别「取件码／提货码／取件密码／开柜码」等明确标签；其次识别「凭号码到某处取件」结构。支持数字、含数字的字母组合和分段号码，以及全角字符、长短横线和同一短信多个取件码。

运单、电话和网址不会被单独猜成取件码。取件码使用保守的 3–12 个字母或数字范围，至少包含一位数字；手机号形式不作为取件码。未知的短信格式可能漏识别，后续应通过真实样本与反例测试完善规则。

不使用具体驿站名称表，站点从短信的目的地、明确标签或带站点后缀的短信签名中提取。也支持独立一行的「柜机／驿站名称 | 地址」，包括全角竖线与换行；只补充缺失地点，不覆盖明确标签中的字段，不把联系电话或网址当作地址。公司使用通用快递公司词表；服务平台名不直接当作快递公司。只有运单尾号时，明确显示「尾号」，不会补全。取件码按文本保存，保留开头的 0。

**只有网址、没有明文取件码的短信不能离线取得取件码。** 没有码的送达消息不创建包裹。RCS / 5G 服务信息不一定产生普通短信广播，本版不监听其他应用通知。可手动粘贴包含明文取件码的文本。

## 构建与验证

使用 JDK 17、Android SDK Platform 35、Build Tools 34.0.0、AGP 8.7.3 和 Gradle 8.9。安装 Android Studio 后打开本目录，同步并构建即可。构建时需要下载依赖，APP 运行不需要网络。

```powershell
.\gradlew.bat :app:assembleDebug :app:parserCheck :app:lintDebug
```

只运行离线解析自检，不依赖 Android SDK：

```powershell
.\scripts\check-parser.ps1
# 可额外检查指定的本地短信样本
.\scripts\check-parser.ps1 -SmsFile 'C:\路径\短信样本.txt'
```

连接专用测试设备或模拟器后，可运行集成测试。数据库测试使用独立数据库和偏好设置，UI 与通知测试会创建并清理自己的合成记录；请在测试设备上运行：

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest
```

每次推送分支都会构建 Release APK、运行解析自检和 Lint，并对齐、签名和验签。Actions 产物包含 APK 和 SHA-256 校验文件。默认使用临时测试密钥。配置原发布密钥后，`main` 会生成正式签名 APK，并在新版本首次构建成功时自动创建 Release。详见 [打包与签名指南](docs/signing.md)。

## GitHub 参考

开发前调研了 [shareven/parcel](https://github.com/shareven/parcel)（MIT）和 [SongZX0106/PickCode](https://github.com/SongZX0106/PickCode)（MulanPSL-2.0）。主要参考 Parcel 的短信与桌面卡片场景及常见号码变体。本项目独立实现解析、本地存储、UI 和小组件。

版本遵循 [Pride Versioning](https://pridever.org/) 的 `PROUD.DEFAULT.SHAME`：值得自豪的发布递增首位，普通发布递增中间位，修复令人尴尬的问题递增末位。Android `versionCode` 独立单调递增。
